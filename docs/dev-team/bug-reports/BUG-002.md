# Bug Report
**ID:** BUG-002
**Title:** TC-163 e2e test fails with "skill-card code element not found" due to missing page-load wait before page.evaluate
**Author:** Remy Dubois (QA Engineer)
**Date:** 2026-06-05
**Build / Commit:** HEAD (main) — tested 2026-06-05 (dark-developer UI restyle pass)

---

## Severity

[x] **Medium** — Feature works but with significant degradation; workaround exists

The underlying behavior being tested IS correct: the `::before` terminal prompt is CSS-only and does NOT appear in `element.textContent` (manually confirmed by running `page.waitForSelector(".skill-card code")` before the evaluate — textContent is the bare command string with no "$ " prefix). The test fails because of a timing defect in the test itself, not a defect in the implementation. However, a failing automated test in a required TC produces a false negative and undermines the regression signal for the `::before` contract going forward. This is medium severity because it is a test-contract defect rather than a product defect, but it blocks green status on the e2e suite.

## Priority

[x] **Must fix before ship** — Blocks release (e2e suite reports 11/12 rather than 12/12; test-plan exit criterion requires 12 passing)

## Steps to Reproduce

1. Run `npm run test:e2e` (or `npx playwright test --grep "TC-163"`).
2. Observe: test `TC-163: code::before prompt does not alter element textContent` fails.

---

## Expected Result

The test navigates to the app, finds the first `.skill-card code` element, reads its `textContent`, and asserts it equals the bare command string `"npx skills add ... -a github-copilot -y"` without a "$ " prefix — confirming the `::before` terminal prompt is CSS-only.

The test should pass because the `::before` content is correctly implemented as a CSS pseudo-element and does not appear in `element.textContent`.

---

## Actual Result

```
Error: page.evaluate: Error: skill-card code element not found
```

The `page.evaluate(() => document.querySelector(".skill-card code"))` call runs before the React app has rendered its skill cards. The `page.goto(APP_PATH)` call resolves when the navigation completes, but the React component tree (which fetches `data/skills.json` asynchronously) has not yet rendered skill cards into the DOM. `document.querySelector(".skill-card code")` returns `null`, and the test throws the custom "element not found" error.

The Playwright page snapshot captured in the error context confirms the app DID eventually render fully (both skill cards and their `<code>` elements are visible in the snapshot), but the snapshot is captured after the test failure, not at the moment of the evaluate call.

---

## Evidence

From `test-results/.../error-context.md` page snapshot: the `<code>` element IS present in the DOM after load:
```
code [ref=e22]: $ npx skills add https://github.com/anthropics/skills --skill frontend-design -a github-copilot -y
```

Manual verification (run with `page.waitForSelector(".skill-card code")` before evaluate):
```json
{
  "textContent": "npx skills add https://github.com/anthropics/skills --skill frontend-design -a github-copilot -y",
  "innerHTML":   "npx skills add https://github.com/anthropics/skills --skill frontend-design -a github-copilot -y"
}
```

The "$ " prefix does NOT appear in `textContent`. The behavior under test is correct.

Note: the page snapshot also shows `code [ref=e22]: $ npx skills add ...` — this "$ " appears in Playwright's accessibility tree snapshot because Playwright's snapshot renderer includes `::before` content in its accessibility representation. This is a snapshot rendering artifact, not a reflection of `element.textContent`. The manual `textContent` check confirms no "$ " in the actual text node.

## Frequency

[x] Happens every time

---

## Hypothesis

The test calls `page.goto(APP_PATH)` and then immediately calls `page.evaluate(...)`. Unlike the other e2e tests in the suite (which all call `await expect(someLocator).toBeVisible()` before interacting with content), TC-163 has no Playwright action or assertion that implicitly waits for the skill cards to render. `page.goto` resolves on navigation completion, not on React component hydration and data fetch completion.

**Fix:** Add `await page.waitForSelector(".skill-card code")` (or `await expect(page.locator(".skill-card code").first()).toBeVisible()`) immediately after `page.goto(APP_PATH)` and before the `page.evaluate` call in TC-163. This is the standard Playwright pattern used by every other test in the suite that accesses rendered content.

The fix is a 1-line addition to `tests/e2e/catalog.spec.ts`. No implementation changes are needed.

---

## Workaround

None that preserves the automated coverage. The test must be fixed.

The underlying implementation is correct and can be manually verified, but the automated gate is broken.
